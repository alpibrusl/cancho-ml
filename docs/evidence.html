Evidence

What each gate checks, against what, how it was shown able to fail, and what it does not prove.

A gate is written before the code it judges. To show a gate can fail there is a mutant: a one-line change to the source (or to a table, a schema or the fixtures) that the gate must catch. A mutant that survives is explained or it is a gap. The oracles are programs written for the purpose, mostly in Python; they check the code against the document, not the document against anything outside it, and the page says where that matters.

Conditions

Every figure below was printed by a script of the repository, run on this tree: one Mac (arm64, Darwin 25.2.0), cancho a4572ea, Python 3.14.5, numpy 2.4.6, scikit-learn 1.8.0. The machine was loaded (a load average of 4 to 7) while the gates and the mutant runs ran. That changes no verdict, because a correctness gate does not depend on the load; it is the reason no time is quoted from these runs. All of it is one machine. A Linux x86-64 run is not done.

What it shows. The classification forests agree with scikit-learn’s to within 0.0011 AUC, and the 1,000,000-row AUC is 0.826176 against 0.827210. The regression forest is 8.1% better (lower RMSE) than scikit-learn’s on R1, against a tolerance of 3%. The algorithms differ: scikit-learn looks for exact thresholds on raw values with its own random generator, this library uses quantile bins. The diagnosis, labelled in the script as not pre-registered: scikit-learn fitted on the bin indices of this library’s own edges gives 2.8737, 3.1% from this library, and without missing cells 0.6%. So most of the gap is the thresholds on a target with a product term whose extreme values an exact splitter isolates; the remaining 3.1% with missing cells is not attributed. What it does not show: that the library is wrong (it is bit-identical to an independent oracle of its own specification), or that it is right (no regression comparison with the same algorithm exists). The tolerance is kept. The maintainer decides whether to keep the rule and leave the gate red, to compare on bin indices only, or to drop the regression comparison.

Determinism

What was verified, and where.

  • The command line: the same data and plan give the same model bytes whatever the working directory, the spelling of the path (./, //), the line ending, a byte order mark, blank lines, the caps given or the repetition; linear and logistic fitted at 1, 2, 4, 8 and 16 threads give one model file; the same command gives the same output five times (D1, docs/cli.md section 6).
  • The libraries, by thread count: linear algebra at 1, 2, 3, 4, 8 and 16 threads; linear models and k-means at 1, 2, 4, 8 and 16 (65 runs), and the k-means model file of ml at the same counts (conformance test and 100,000-row oracle cases); trees and forests at 1, 2, 3, 4, 5, 8 and 16, and the benchmark scripts check the same equality at 100,000 and 1,000,000 rows (by hash, without an oracle at 1,000,000).
  • Not verified: the same bytes on another machine. Everything above ran on one Mac (arm64). The design argues the arithmetic is the same on Linux x86-64 (IEEE binary64, no fused multiply-add, no platform libm), and that is unverified.
  • The stream kinds: the splits draw from kinds 4, 5 and 6, the tree and k-means streams from 1, 2 and 3, so a split and a forest started from one seed share no draws (docs/rng.md).

What this does not prove

  • Nothing here is a claim about speed. No gate measures it; the benchmarks page has the timings and their load.
  • An oracle written from the same text shows the code does what the document says, not that the document is right. The gates that compare with an outside implementation (Python float(), numpy, scikit-learn) say where they agree and where only within a tolerance.
  • The command line builds six models. The wiring of linear and logistic, of the tree and forest, and of k-means has its own gates, oracle, mutants and admission script (docs/wiring.md, docs/wiring-trees.md, docs/wiring-kmeans.md, docs/modules.md). The oracles of the tree, forest and k-means files are written from the same document as the code, and scikit-learn is the outside check: within bounds that the small files make loose for the trees, and for k-means only with the initial centres given to it, since the two programs draw different ones. k-means is not scored against a label and has no stopping rule.
  • One machine, one operating system, one compiler revision. A second-machine run (D2) is not done.
  • Not run by these gates: the benchmarks, and the 1,000,000-row identity and timing runs of the tree library beyond the defaults.
  • Open items: the red gate above, and check.sh, which needs ../ml-data and the network for cancho install (docs/status.md).

To run them: sh scripts/check.sh runs the gates; the mutant runs are python3 scripts/mutants_NAME.py for core, paths, linalg, models, metrics, tree, reader, cat, enc, st, cli, wire, wire_trees, wire_kmeans and pipe, each with --check to see that every edit still applies without building anything.
