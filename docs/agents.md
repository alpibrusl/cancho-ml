# cancho-ml, as an agent reads it

Generated by `scripts/site.py` from the built binary, `docs/status.md` and the manifests of `lib/models`. The page [index.html](index.html) is the same facts for a person.

cancho-ml fits, applies, scores and serves classical models on a CSV. Every refusal is data: a rule tag, an exit code and, where one can exist, a command that fixes it.

## Ask the tool, not this file

```console
$ ml skill          # this guide, from the binary, in Markdown
$ ml introspect     # one JSON document: 82 flags, 30 limits, 138 refusal rules, the authority
$ ml-mcp            # 12 tools over MCP, generated from the same table
```

## An answer and a refusal

Standard output is one JSON line, schema `ml.v1`: `{ok, command, schema, data, error, errors, meta}`. Match on `error.rule`, never on `message`. A `repair` of kind `retry` is an argv that can be run as it stands and never widens what the tool may touch.

```json
{"ok":false,"error":{"rule":"ml.input.missing-value","hint":"add an impute step for the columns, for example impute column=a,b strategy=mean.","repair":{"kind":"retry","argv":["ml","fit","--model","logistic","--target","virginica","--output","iris-gaps.ml","iris_gaps.csv","--step","impute column=sepal_width_cm strategy=mean"]}}} …
```

Exit codes:

| exit | `code` | meaning |
|---:|---|---|
| 0 | `SUCCESS` | what was asked was done; zero matches is success |
| 1 | `GENERAL_ERROR` | the operating system failed mid-operation, or the tool caught a bug in itself |
| 2 | `INVALID_ARGS` | the invocation is malformed or names something of the wrong kind; nothing was read |
| 3 | `NOT_FOUND` | a named input does not exist |
| 4 | `PERMISSION_DENIED` | the operating system refused, or the tool's own confinement did |
| 5 | `CONFLICT` | state is not what the caller said it would be |
| 8 | `PRECONDITION_FAILED` | the answer is no, or a limit was reached |
| 9 | `DRY_RUN` | a --dry-run completed; planned_actions lists what an apply would do |

## Verbs

`fit`, `predict`, `describe`, `cv`, `eval`, `importance`, `dump`, `runs`. Models: constant (supported), linear (supported), logistic (supported), kmeans (supported), tree (supported), forest (supported), boost (supported), softmax (experimental), recommend (experimental).

```console
$ ml fit --model logistic --target y --step "scale column=* kind=standard" --split train=0.8 --seed 3 --track runs --output m.ml train.csv
$ ml predict --model-file m.ml new.csv     # the schema, the steps and the model are in the file
$ ml runs verify runs ID                   # re-fits from the record and compares the model's SHA-256
$ ml-serve --model-file m.ml --port 8080   # listens on 127.0.0.1; --bind all needs --token-file
```

## What holds

- The same input, plan and seed give the same model bytes at any `--threads`. 112 lines of hashes equal a committed golden on 3 platforms.
- A model is one file ending in a SHA-256 of the rest; a flipped byte is refused with `ml.model.checksum`.
- `ml` has no network; `ml-predict` and `ml-serve` write no file. The compiler derives this and a committed manifest checks it.
- 681 conformance tests pass; 1,854 of 1,935 deliberate faults are caught and each of the 81 others is explained.

## What is not claimed

- No speed is claimed. One pre-registered gate is red: the regression forest differs from scikit-learn's by 8.1% against a tolerance of 3%.
- Any platform, input or compiler revision beyond those in [status.md](https://github.com/alpibrusl/cancho-ml/blob/main/docs/status.md) is untested. No release is published; the source is the way in.
