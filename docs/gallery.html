Gallery

One card per kind of model and per option, then what is asked for and not built. Each picture is drawn from the output of the command under it, run on the files in docs/examples/data or on a small synthetic set. The dashed cards are not built: their sketches are drawings, and the line under each is what the command answers today.

Cards

model

constant: the baseline to beat

The mean of the target, fitted and scored like any model. If a model cannot beat it, it learned nothing.

  • RMSE of the constant model 70.46; of the best of the four 56.4
$ ml fit --model constant --target progression --output c.ml diabetes_train.csv
$ ml eval --model-file c.ml diabetes_test.csv
model

linear: least squares, ridge with --l2

Exact sums in a fixed order, so the coefficients are the same on every platform.

  • R² 0.359, RMSE 56.4 on rows the model never saw
$ ml fit --model linear --target progression --step "scale column=* kind=standard" --l2 0.1 --output l.ml diabetes_train.csv
$ ml predict --model-file l.ml diabetes_test.csv
model

logistic: Newton's method, with the probability

Two classes, a label and the probability of the positive one with --proba.

  • accuracy 1, ROC-AUC 1, log-loss 0.203
$ ml fit --model logistic --target virginica --step "scale column=* kind=standard" --l2 0.1 --output g.ml iris_train.csv
$ ml predict --model-file g.ml --proba iris_test.csv
model

softmax: three or more classes

One model for any number of classes, with a confusion matrix.

Synthetic: three seeded blobs written by scripts/gallery.py, because the bundled files have two classes.

  • accuracy 0.95; confusion matrix in the answer: [11,0,0][2,15,0][0,0,12]
$ ml fit --model softmax --target class --l2 0.1 --output s.ml blobs_train.csv
$ ml eval --model-file s.ml blobs_test.csv
model

tree: a CART tree you can print

ml dump prints every node: the column, the threshold and the rows it holds.

  • 13 nodes, depth 3; accuracy 1 on the test file
$ ml fit --model tree --task classification --target virginica --max-depth 3 --output t.ml iris_train.csv
$ ml dump --model-file t.ml
model

forest: bagged trees, and which columns they used

Trees fitted in parallel, with the same bytes at any thread count. ml importance says which columns mattered.

  • accuracy 0.951 on 143 held-out rows; the six columns carry 0.188 of the decrease
$ ml fit --model forest --task classification --target benign --trees 50 --seed 1 --output rf.ml breast_cancer_train.csv
$ ml importance --model-file rf.ml
model

boost: gradient-boosted trees, with early stopping

Rounds fitted to the gradients of the loss; --early-stopping stops when a held-out part stops improving.

  • RMSE 61.98, against 56.4 for the linear model and 57.95 for the forest
$ ml fit --model boost --task regression --target progression --rounds 100 --learning-rate 0.1 --seed 1 --output b.ml diabetes_train.csv
$ ml eval --model-file b.ml diabetes_test.csv
model

kmeans: clusters with no target

A seeded initialisation and a fixed number of passes: the same clusters every time.

  • k = 3; the centres are the rings; each test row gets its cluster, and --distance adds its squared distance
$ ml fit --model kmeans --k 3 --seed 1 --drop virginica --output k.ml iris_train.csv
$ ml predict --model-file k.ml --drop virginica iris_test.csv
model

ranking: pairwise or LambdaRank

Rows ranked inside a group (a query), scored by NDCG. The group stays on one side of every split.

Synthetic: 30 seeded queries of 8 rows, written by scripts/gallery.py; scored on the rows it was fitted on, to show the flags.

  • NDCG@5 0.992 (pairwise) and 0.973 (LambdaRank), on the training queries
$ ml fit --model boost --task lambdarank --group qid --target rel --rounds 60 --output r.ml rank.csv
$ ml eval --model-file r.ml --group qid --rank-k 5 rank.csv
model

recommend: what a user has not seen yet

Matrix factorisation (ALS) from a log of user, item, rating; predict --for answers the top items a user has not rated.

Synthetic: 30 users in three taste groups, written by scripts/gallery.py.

  • 30 users, 12 items, 199 interactions; the loss is 97
  • items the user already rated are left out (--keep-seen keeps them)
$ ml fit --model recommend --user user --item item --rating rating --factors 3 --seed 1 --output rec.ml ratings.csv
$ ml predict --model-file rec.ml --for who --top 5 who.csv
option

text columns, by a written rule

--cat names the text columns; a step encodes them; a new category at predict time is counted, never guessed.

  • the model file holds 6 species, 3 city; describe lists them
$ ml fit --model logistic --target adopted --drop id --cat species,city --step 'encode column=species,city kind=onehot; scale column=* kind=standard' --output p.ml pets.csv
$ ml describe --model-file p.ml
option

splits that cannot leak

--split-by time:COLUMN trains on the past and scores the newest rows; --stratify and --split-group keep classes and groups apart.

  • 90 older rows train, 30 newer rows are scored: the model never sees the future
$ ml fit --model linear --target basket --drop customer,visit_date --split-by time:visit_date --split train=0.75 --output v.ml visits.csv
option

cross-validation, fitted per fold

Every step is fitted on the training rows of each fold only, so a fold cannot leak into its own scoring.

  • mean accuracy 0.92, sample std 0.11 over 5 folds
$ ml cv --model logistic --target virginica --step "scale column=* kind=standard" --l2 0.1 --folds 5 --seed 3 iris_train.csv
option

the same bytes at any thread count

--threads changes the time, not one byte of the model file.

  • SHA-256 2966e7472c91… at one thread and at eight: equal
$ ml fit --model forest ... --seed 1 --threads 1 --output th1.ml breast_cancer_train.csv
$ ml fit --model forest ... --seed 1 --threads 8 --output th8.ml breast_cancer_train.csv
option

look before it writes

--dry-run reads, checks and fits, then says what it would write and exits 9. Nothing is written.

  • exit status 9; planned_actions names the file, its size and its SHA-256
$ ml fit --model linear --target progression --output dry.ml --dry-run diabetes_train.csv
