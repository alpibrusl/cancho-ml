Machine learning on a CSV that says no clearly and repeats exactly.

cancho-ml fits, scores and serves classical models from the command line. When it cannot do what you asked, it names the rule and prints the command that fixes it.

Real output, replayed; it is not a live session. The first two logs are scripts/demo.sh, which runs the built ml and ml-serve on the iris files of the worked examples: two tracked fits, their comparison and replay, a score on the training file and on another, then a server on a free port and two requests. The third is a refusal and its repair. What is cut: a hash or run id shows 12 of its 64 digits, the two answers of the server and the JSON lines of the third log keep the members that matter (marked …), the demo prints compare, verify and eval as one line each, and the port is 8080 and the temporary directory a dot. Without JavaScript the three logs are shown in full.

Trust the check, not the claim

A model you cannot reproduce or audit is a guess. Five things that are checked, each by a script that can fail.

The same bytes

112 hashes of model files and printed answers (28 fits) equal a committed golden on 3 platforms. One changed byte fails the gate.

Refusals are data

One JSON line with a rule tag, an exit code and, where one can exist, a command that fixes it. An empty cell, an unread text column or a damaged file stops the run.

One checked file

A model is one file that ends in a SHA-256 of the rest, so a flipped byte is refused. ml-predict and ml-serve read it and print the text ml predict prints.

Authority you can read

What each program may touch is derived by the compiler and checked against a committed manifest. ml has no network; ml-predict and ml-serve write no file.

Experiments you can replay

Every fit can write a run record (--track). ml runs compare shows what differs and the metrics side by side; ml runs verify re-fits and reproduces the model’s hash. eval says whether it scored the training file (on) and counts the cells outside its range.

How it works

A CSV becomes a plan of steps, a fit with sums in a fixed order, and one model file. Anything the tool cannot accept goes back to you with its repair.

In words: your CSV goes to a plan of steps, then to a fit with sums in a fixed order, then to one model file. predict, eval and ml-serve read that file. A CSV or a plan the tool cannot accept is refused with a rule tag, an exit code and a repair; you run the repair and try again.

One command, one model file, one server

One verb, seven models: constant, linear, logistic, k-means, tree, forest and boost. The file the fit writes is all a later command needs, and a server needs nothing else.

# any of the seven models, one verb; --track keeps a run record
$ ml fit --model logistic --target virginica --step "scale column=* kind=standard" --l2 0.1 --split train=0.8 --seed 3 --track runs --output iris.ml iris_train.csv
# two runs: what differs, and the metrics side by side
$ ml runs compare runs A C
# replay a run: re-fit from its record and compare the SHA-256 of the model file
$ ml runs verify runs A
# the same file over HTTP: it listens on 127.0.0.1 unless --bind all is given
$ ml-serve --model-file iris.ml --port 8080
# one request
$ curl -s localhost:8080/predict -d '{"sepal_length_cm":5.6,"sepal_width_cm":2.8,"petal_length_cm":4.9,"petal_width_cm":2.0}'

Splits and folds

--split train=0.8 --seed 3 holds rows out and scores them. --stratify keeps the class mix, --split-by time:COLUMN holds out the newest rows, --split-group COLUMN keeps a group on one side, and ml cv --folds 5 scores the folds.

Text columns, by a written rule

Columns declared with --cat are encoded (one-hot, label, frequency or hash) by a step; the model file holds what predict needs, and a new category is counted, not guessed.

Read by a program

ml introspect prints every flag, limit and refusal rule (116 rules) as one JSON document, and ml skill prints a guide for an agent. ml-mcp offers 12 tools over MCP, generated from the same table. ml importance says which columns a model relies on, and ml dump prints a tree.

ml-serve answers one request at a time and has no TLS. It listens on 127.0.0.1 unless you pass --bind all, which needs a token file (--token-file). The guide shows the requests, the run records and the splits, each with its real output.

Conditions. The hashes cover every model file and printed answer of 28 fits (every model kind, 1 and 8 threads) on the bundled example data; they equal the golden on macOS arm64, Linux x86-64 and Linux aarch64: the workflow runs the gate on 4 GitHub runners (ubuntu-24.04, ubuntu-26.04, ubuntu-24.04-arm, macos-26), and a Mac, an Ubuntu workstation and a Raspberry Pi 5 ran it by hand. The last run of those runners (88 equal lines on each, 2026-10-15) was at the previous compiler pin; no run exists at 0207556. Any other platform, input or compiler revision is untested. The tests passed in one run of scripts/check.sh on a Linux x86-64 machine; the mutant counts come from runs on several commits and two compilers (Evidence says which suite ran where). Limits. One pre-registered gate is red: the regression forest differs from scikit-learn’s by 8.1% against a tolerance of 3%. No speed is claimed: the command line is not timed, and the timings of its libraries come from a loaded machine (Benchmarks).

Try it

Build it from source. You need git, Rust, clang and python3, and the network for the clones and cancho install.

git clone https://github.com/alpibrusl/cancho                           # the compiler
git clone https://github.com/alpibrusl/cancho-ml && cd cancho-ml
REV=$(sed -n 's/^cancho *= *"\([0-9a-f]*\)".*/\1/p' cancho.toml)        # the compiler these sources need
(cd ../cancho && git fetch -q origin && git checkout "$REV" && cargo build --release -p cancho)
export PATH=$PWD/../cancho/target/release:$PWD/build:$PATH
cancho install && cancho build --bin ml                                 # install fetches the pins (network); builds build/ml

Then run the commands above on the CSVs in docs/examples/data, or build the server (cancho build --bin ml-serve) and run sh scripts/demo.sh, which prints what the first two logs replay. The workflow builds ml, ml-predict and ml-serve for Linux x86-64, Linux aarch64 and macOS arm64 and attaches them with SHA-256 files to a release when a tag v* is pushed; no release is published today, so the source is the way in. The guide has the full quick start.
