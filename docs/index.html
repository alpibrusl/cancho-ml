Machine learning on a CSV that says no clearly and repeats exactly.

cancho-ml fits, scores and serves classical models from the command line. When it cannot do what you asked, it names the rule and prints the command that fixes it.

A real run of the built ml on the iris files of the worked examples: a fit with rows held out, a predict, an eval, then a refusal and its repair. It is a replay of that output, not a live session. Each answer is one JSON line; the replay keeps the members that matter and cuts the rest (marked …), and shows 16 digits of each SHA-256. Without JavaScript the whole log is shown.

Trust the check, not the claim

A model you cannot reproduce or audit is a guess. Four things that are checked, each by a script that can fail.

The same bytes

88 hashes of model files and printed answers (22 fits) equal a committed golden on 3 platforms. One changed byte fails the gate.

Refusals are data

One JSON line with a rule tag, an exit code and, where one can exist, a command that fixes it. An empty cell, an unread text column or a damaged file stops the run.

One checked file

A model is one file that ends in a SHA-256 of the rest, so a flipped byte is refused. ml-predict and ml-serve read it and print the text ml predict prints.

Authority you can read

What each program may touch is derived by the compiler and checked against a committed manifest. ml has no network; ml-predict and ml-serve write no file.

How it works

A CSV becomes a plan of steps, a fit with sums in a fixed order, and one model file. Anything the tool cannot accept goes back to you with its repair.

In words: your CSV goes to a plan of steps, then to a fit with sums in a fixed order, then to one model file. predict, eval and ml-serve read that file. A CSV or a plan the tool cannot accept is refused with a rule tag, an exit code and a repair; you run the repair and try again.

One command, one model file

Six models behind one verb: constant, linear, logistic, k-means, tree and forest. The file the fit writes is all a later command needs.

# any of the six models, one verb each
$ ml fit --model forest --task classification --trees 20 --seed 7 --target virginica --output iris-forest.ml iris_train.csv
$ ml predict --model-file iris-forest.ml --proba --limit 3 iris_test.csv
# what a model file requires of a caller, as data
$ ml describe --model-file iris-forest.ml
# the prediction half, a separate binary with no write and no thread
$ ml-predict predict --model-file iris-forest.ml --proba --limit 3 iris_test.csv
# the same file over HTTP, one request at a time (see the guide for the requests and what it answers)
$ ml-serve --model-file iris-forest.ml --no-token --port 8080

Rows held out, with a seed

--split train=0.8 --seed 3 holds rows out and scores them; the same seed holds out the same rows. The seed also draws the forest's trees and the k-means start.

Text columns, by a written rule

Columns declared with --cat are encoded (one-hot, label, frequency or hash) by a step; the model file holds what predict needs, and a new category is counted, not guessed.

Read by a program

ml introspect prints every flag, limit and refusal rule (79 rules) as one JSON document, and ml skill prints a guide for an agent.

ml-serve answers one request at a time, listens on every address of the host and so needs --token-file or --no-token; it has no TLS. The guide shows the requests and what comes back.

Measured, not promised

Counts read from the repository’s own gates and documents when the page is built.

Conditions. The hashes cover every model file and printed answer of 22 fits (every model kind, 1 and 8 threads) on the bundled example data; they equal the golden on macOS arm64 and Linux x86-64, and on Linux aarch64 (a Raspberry Pi 5), each run by hand. The workflow runs the same gate on the first two; no run on a GitHub runner is recorded in the repository. Any other platform, input or compiler revision is untested. The tests and mutants ran on one Mac with compiler a4572ea; the counts of five mutant suites were measured on another commit (Evidence says which). Limits. One pre-registered gate is red: the regression forest differs from scikit-learn’s by 8.1% against a tolerance of 3%. No speed is claimed: the command line is not timed, and the timings of its libraries come from a loaded machine (Benchmarks).

Try it

Build it from source. You need git, Rust, clang and python3, and the network for the clones and cancho install.

git clone https://github.com/alpibrusl/cancho                           # the compiler
git clone https://github.com/alpibrusl/cancho-ml && cd cancho-ml
REV=$(sed -n 's/^cancho *= *"\([0-9a-f]*\)".*/\1/p' cancho.toml)        # the compiler these sources need
(cd ../cancho && git fetch -q origin && git checkout "$REV" && cargo build --release -p cancho)
export PATH=$PWD/../cancho/target/release:$PWD/build:$PATH
cancho install && cancho build --bin ml                                 # install fetches the pins (network); builds build/ml

Then run the commands above on the CSVs in docs/examples/data. The workflow builds ml, ml-predict and ml-serve for Linux x86-64 and macOS arm64 and attaches them with SHA-256 files to a release when a tag v* is pushed; no release is published today, so the source is the way in. The guide has the full quick start.
