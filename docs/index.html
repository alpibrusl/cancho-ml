Early, alpha · one model is built

Classical ML as a command line an agent can read.

Fit, apply and score a model on a CSV, with exact sums, bounded resources, structured refusals and a machine-verifiable authority.

A command line and flags, not a chat box. The same tool for a person and for an agent. Today the one model it can build is the constant one, the training mean or the majority class: a baseline with the whole path around it. The other models exist as tested libraries and are not wired in yet.

Why cancho-ml?

Most ML tools optimise for how many models they offer. ml is built to be predictable first, and so far offers one.

  • Explicit typesA column is an integer, a decimal or a float, read to the nearest double by cancho-table’s exact reader. nan, inf, an empty cell and a cell that is not a number are refused with the line and the column. docs/reader.md
  • Exact where a sum decidesThe mean of an integer or decimal target and the sum of squared errors are exact integers, not floats; a float target is summed exactly and rounded once. A test compares every digit with Python’s fractions.Fraction. The rmse is three IEEE steps after the exact sum, and says so. docs/cli.md
  • The same bytesA model file holds no timestamp, host or path. The same data and plan give the same bytes whatever the working directory or the spelling of the path. The libraries keep their bytes at 1 to 16 threads on one Mac; across machines it is not tested. Evidence
  • Bounded resource useRows, columns, cells, line length, model size and log size each have a limit flag with a default and a ceiling, checked before anything sized by the input is allocated (the limits). No gate measures memory use.
  • No implicit network accessThe authority row lists what the program can reach: no net_out, net_in, ffi or clock, no standard input and no write by path. cancho authority derives it, and scripts/manifest.py --check fails if the binary differs from the committed manifest.
  • Machine-readable errorsOne JSON line against a schema (ml.v1). A refusal is {code, rule, message, hint, repair, detail} with a stable <area>.<name> rule tag. docs/design.md
  • Repair hintsA refusal says how to fix the request: an argv to run as it stands, or why there is none.
  • A model file that checks itselfCML1: sections, tensor records and a SHA-256 trailer. Every truncation and every flipped byte of a small model is refused. Evidence
  • Capability introspectionml introspect prints the flags, limits, rules and authority; ml skill prints a guide for an agent. Excerpts below

Fit, predict and score a regression

fit reads the CSV, takes --target as the column to predict and writes the model with --output. price is a whole-number column, so its mean is an exact decimal with six more fractional digits than the column has. predict needs the same columns as the fit, minus the target; eval scores a model on a CSV that has the target.

$ ml fit --target price --output houses.ml houses.csv

Fit and score a classification

--task classification needs an integer target with exactly two values. The prediction is the class with more rows (the smaller label on a tie) and the probability is the share of the larger label’s rows, to six digits. predict comes in pages: --limit and --from, and next is where to continue. This example uses shop.csv: id,visits,spend,bought and six rows, four of them with bought = 1.

$ ml fit --task classification --target bought --output shop.ml shop.csv
{"ok":true,"command":"ml","schema":"ml.v1","data":{"model":"constant","task":"classification","rows":6,"columns":4,"target":"bought","path":"shop.ml","bytes":363,"sha256":"dc81e1ce7ff30ea56c12ec49a39cd808e55f558d049f0858ab136f213f385dbd","written":true,"summary":{"classes":[0,1],"counts":[2,4],"majority":1,"probability":"0.666667"}},"meta":{"version":"0.1.0"}}
$ ml predict --model-file shop.ml shop.csv --limit 2 --from 1
{"ok":true,"command":"ml","schema":"ml.v1","data":{"model":"constant","task":"classification","columns":["label","probability"],"rows":[["1","0.666667"],["1","0.666667"]],"row_count":2,"total_rows":6,"truncated":true,"next":{"from":3}},"meta":{"version":"0.1.0"}}
$ ml eval --model-file shop.ml shop.csv

Read floats exactly

A cell with an exponent, a leading or trailing point or more than 12 digits is a float without being named (--float NAMES forces it). It is read to the nearest double, ties to even. The mean of a float target is the exact sum of the doubles over the count, rounded once, and written as the shortest decimal that reads back to the same double. This example uses sensor.csv: id,x,reading and the readings 1e1, 2.75, 3e-1 and 5.5.

$ ml fit --target reading --output sensor.ml sensor.csv
{"ok":true,"command":"ml","schema":"ml.v1","data":{"model":"constant","task":"regression","rows":4,"columns":3,"target":"reading","path":"sensor.ml","bytes":306,"sha256":"182d75563021836f542c0542daf74d2ddfcd9608b6e2ac769beb969d2b52ff44","written":true,"summary":{"mean":"4.6375"}},"meta":{"version":"0.1.0"}}
$ ml eval --model-file sensor.ml sensor.csv
{"ok":true,"command":"ml","schema":"ml.v1","data":{"model":"constant","task":"regression","rows":4,"metrics":{"rmse":"3.6012801543340114","sse":"51.876875","prediction":"4.6375"}},"meta":{"version":"0.1.0"}}

Check before you write

An existing output is refused unless --overwrite is given. --dry-run reads, checks and fits, runs every check the write would, and answers with the file it would write: exit 9, and nothing created or changed. The file is written to a temporary name beside the final one and renamed over it, so a reader never sees half a model.

$ ml fit --target price --output houses.ml houses.csv
{"rule": "conflict.exists", "hint": "use --overwrite to replace it, or name another file", "detail": {"path": "houses.ml"}}
# exit status 5; the rule, hint, detail of the JSON line it prints
$ ml fit --dry-run --overwrite --target price --output houses.ml houses.csv
{"ok":true,"command":"ml","schema":"ml.v1","data":{"model":"constant","task":"regression","rows":5,"columns":4,"target":"price","path":"houses.ml","bytes":340,"sha256":"299879cc4b9be8afb5c6029aa8c635693162dc7a6d6ef564a4a1a66b83f4f1d8","written":false,"summary":{"mean":"218000.000000"}},"dry_run":true,"planned_actions":[{"op":"replace","path":"houses.ml","bytes":340,"sha256":"299879cc4b9be8afb5c6029aa8c635693162dc7a6d6ef564a4a1a66b83f4f1d8"}],"meta":{"version":"0.1.0"}}
# exit status 9; a dry run: nothing was written

A damaged model is refused

The model file ends with the SHA-256 of every byte before it. Here one byte of houses.ml was changed and the file saved as damaged.ml.

$ ml eval --model-file damaged.ml houses.csv
{"rule": "ml.model.checksum", "hint": "the file changed after it was written"}
# exit status 8; the rule, hint of the JSON line it prints

Built to be read by an agent

ml introspect and ml skill are generated from the same tables the code parses its flags with, so they cannot disagree with the program. An agent can learn the interface, the limits, the rules and the authority from the binary itself. A test checks that every flag and every rule is in the table, in introspect, in skill, in the schema and in a fixture. Match on error.rule, not on the message; repair is null or an argv that can be run as it stands; --dry-run exits 9 and writes nothing. The exit codes are cancho’s agent-toolbox classes: 0 done, 1 the operating system failed, 2 a malformed call, 3 not found, 4 refused, 5 conflict, 8 the answer is no or a limit was reached, 9 a dry run completed.

The guarantees block of introspect and parts of skill are the pinned contract package’s generic text. They are wrong or too narrow for ml in six places (for example “read-only: it never writes”, although fit writes), listed in docs/cli.md section 8 so that nobody reads them as claims.

What it cannot do yet

  • Only the constant model is reachable. Linear regression (with ridge), logistic regression (binary), k-means, decision trees and random forests exist as libraries with independent oracles; no verb calls them. Wiring one means a model kind in the file writer and reader, its rule tags in introspect and a fixture each (docs/integration.md section 6).
  • No transforms and no pipeline (impute, scale, encode). They are being built; the plan is a design in docs/design.md section 4.2. fit refuses an empty cell, and a column of text has to be dropped.
  • Binary classification only, and no --threads in ml: the libraries are threaded and keep their bytes, the command line runs on one thread.
  • One gate is red. The regression forest against scikit-learn’s: RMSE 8.1% apart where the tolerance was 3%. The algorithms differ (histogram against exact splits), the stage attributed most of the gap to that, the tolerance was not moved, and the decision is the maintainer’s (evidence).
  • Not tested across machines. The bytes are verified on one Mac, arm64. A Linux x86-64 run is not done.
  • The reader’s home is temporary. It compiles cancho-table’s numeric files through a local clone until cancho-table#44 (a draft) merges.
  • Not started: the MCP server and ml-serve (issue #16).
  • Not planned in v1: neural networks and a GPU path. Boosting, naive Bayes, k-NN and multiclass are in the plan and not built.

Nothing in this list is a promise. docs/status.md has it as a table, with the document that measured each item.

Quick start

You need git, Rust, clang and Python 3, and network access for the clones and for cancho install, which fetches the pinned cancho-tools modules. Until cancho-table#44 merges, the reader depends on cancho-table through a local-development arrangement: cancho.toml names the six numeric files of a read-only clone at ../cancho-table-main, pinned by table.pin and checked by scripts/check_table_pin.sh. Nothing is copied. On a 16-core Mac with the compiler already built, cancho build --bin ml took 2.9 seconds once; the compiler build and the clones are extra.

git clone https://github.com/alpibrusl/cancho
git clone https://github.com/alpibrusl/cancho-table cancho-table-main   # LOCAL-DEV: its numeric modules
git clone https://github.com/alpibrusl/cancho-ml && cd cancho-ml
REV=$(sed -n 's/^cancho *= *"\([0-9a-f]*\)".*/\1/p' cancho.toml)
(cd ../cancho && git fetch -q origin && git checkout "$REV" && cargo build --release -p cancho)
(cd ../cancho-table-main && git checkout -q "$(sed -n 's/^rev //p' ../cancho-ml/table.pin)")
sh scripts/check_table_pin.sh
export PATH=$PWD/../cancho/target/release:$PWD/build:$PATH
cancho install && cancho build --bin ml      # builds build/ml

cat > houses.csv <<'EOF'
id,rooms,area,price
1,2,48.5,180000
2,3,71.25,240000
3,3,64,215000
4,4,98.5,335000

EOF

Built in cancho, with an authority the compiler wrote

cancho is a language whose compiler writes down what a program may do (cancho authority). For ml that is the line below: it can read its arguments and the files named on its command line, allocate memory, create, append to, rename and remove files beneath a directory it opened itself, and write to the terminal. It cannot use the network, call foreign code, read the clock, read standard input or write a file by path. There is no conc, because ml has no --threads. The path extent is a run-time value, so the row names the verb, not the place: fs_read("").

# manifests/ml.authority.json
ml    args, dir_read, dir_write, err_write, file_read, file_write, fs_read(""), heap, io_write
# bounded: true; foreign symbols: none; net_out, net_in, ffi, clock: absent

How fast

No speed is claimed for ml: the command line has not been timed. The libraries under it were timed on one shared Mac (arm64, 16 cores) at a load average of 2.4 or more, so every figure is flagged load >= 2 and none is a quiet-machine number. A serial rerun on a quiet machine is pending. They are on the benchmarks page with their conditions, and these are the shape of them.

  • Where it is slower. Dense float linear algebra: on the 29 gate shapes, one thread, 8 match numpy and Accelerate and 21 do not, from 1.05 to 14.9 times slower; square gemm is 13.8 to 16.5 times slower. The same algorithm in C takes about as long, so the gap is the vendor library and the language (no SIMD vector type). Logistic regression is 1.4 to 1.5 times slower than numpy’s same algorithm. A log-loss is 3.0 times slower than a thin numpy version.
  • Where it is not. The triangular solves and small Cholesky match; k-means is level with scikit-learn (306 against 330 ms on 1,000,000 rows); the AUC took 24 ms against 86 ms for a thin numpy version on 1,000,000 scores.
  • Forests. Ten trees on 100,000 rows fit in 0.0516 s on one thread, where scikit-learn’s exact-split RandomForestClassifier took 1.06 s. Not a speed claim: the algorithms differ (64 quantile bins against exact thresholds).

Status: early, alpha

  • What is listed above works and is tested. The command line builds one model. Nothing here is for production.
  • One pre-registered gate is red, and the speed figures are from a loaded machine. Evidence and benchmarks say exactly what each shows.
  • The program is built with one pinned compiler version, and that compiler is still changing.
