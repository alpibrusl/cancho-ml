Early, alpha · three models are built

Classical ML as a command line an agent can read.

Fit, apply and score a model on a CSV, with exact sums, bounded resources, structured refusals and a machine-verifiable authority.

A command line and flags, not a chat box. The same tool for a person and for an agent. Today it builds three models: the constant one (the training mean or the majority class, a baseline with the whole path around it), linear regression and logistic regression, the last two through a pipeline of steps that is fitted on the training rows and stored with the model in one file. k-means, trees and forests are tested libraries that no verb calls.

A model through the pipeline

A float CSV with an empty cell: the plan has to say what to do with it, or the fit is refused with a repair. Then the plan written out — impute, standardise, a logistic regression — predict with probabilities (the empty cell of the new rows is filled with the mean stored in the model) and score. Every line is what the built program prints.

Why cancho-ml?

Most ML tools optimise for how many models they offer. ml is built to be predictable first, and offers three models and a pipeline.

  • Explicit typesA column is an integer, a decimal or a float, read to the nearest double by cancho-table’s exact reader. nan, inf, an empty cell and a cell that is not a number are refused with the line and the column. docs/reader.md
  • Exact where a sum decidesThe mean of an integer or decimal target and the sum of squared errors are exact integers, not floats; a float target is summed exactly and rounded once. A test compares every digit with Python’s fractions.Fraction. The rmse is three IEEE steps after the exact sum, and says so. docs/cli.md
  • The same bytesA model file holds no timestamp, host or path. The same data, plan and seed give the same bytes whatever the working directory or the spelling of the path, and at every --threads from 1 to 16 (linear and logistic, one Mac); across machines it is not tested. Evidence
  • Bounded resource useRows, columns, cells, line length, model size, log size and the categorical dictionary each have a limit flag with a default and a ceiling, checked before anything sized by the input is allocated (the limits). Peak memory is measured for one case, the reader’s refusal of a 200 MB file (1.5 MB); no gate measures the memory of a fit.
  • No implicit network accessThe authority row lists what the program can reach: no net_out, net_in, ffi or clock, no standard input and no write by path. cancho authority derives it, and scripts/manifest.py --check fails if the binary differs from the committed manifest.
  • Machine-readable errorsOne JSON line against a schema (ml.v1). A refusal is {code, rule, message, hint, repair, detail} with a stable <area>.<name> rule tag. docs/design.md
  • Repair hintsA refusal says how to fix the request: an argv to run as it stands, or why there is none.
  • A model file that checks itselfCML1: sections, tensor records and a SHA-256 trailer. Every truncation and every flipped byte of a small model is refused. Evidence
  • Text columns, encoded by a written ruleColumns declared with --cat are read into a bytewise-sorted dictionary. encode (one-hot, label), freq and hash (SHA-256) turn them into numbers, with a rare-category bucket and rules for an unseen string and an empty cell; a Python oracle agrees bit for bit on 515 runs. A fit with such a step writes no model file, so --split fits and scores in one call. Evidence
  • Capability introspectionml introspect prints the flags, limits, rules and authority; ml skill prints a guide for an agent. Excerpts below

Fit, predict and score a regression

fit reads the CSV, takes --target as the column to predict and writes the model with --output. price is a whole-number column, so its mean is an exact decimal with six more fractional digits than the column has. predict needs the same columns as the fit, minus the target; eval scores a model on a CSV that has the target.

Fit and score a classification

--task classification needs an integer target with exactly two values. The prediction is the class with more rows (the smaller label on a tie) and the probability is the share of the larger label’s rows, to six digits. predict comes in pages: --limit and --from, and next is where to continue. This example uses shop.csv: id,visits,spend,bought and six rows, four of them with bought = 1.

Read floats exactly

A cell with an exponent, a leading or trailing point or more than 12 digits is a float without being named (--float NAMES forces it). It is read to the nearest double, ties to even. The mean of a float target is the exact sum of the doubles over the count, rounded once, and written as the shortest decimal that reads back to the same double. This example uses sensor.csv: id,x,reading and the readings 1e1, 2.75, 3e-1 and 5.5.

Check before you write

An existing output is refused unless --overwrite is given. --dry-run reads, checks and fits, runs every check the write would, and answers with the file it would write: exit 9, and nothing created or changed. The file is written to a temporary name beside the final one, synced and renamed over it; that this keeps a reader from seeing half a model, and two writers racing on one output, were not tested.

$ ml fit --target price --output houses.ml houses.csv
{"rule": "conflict.exists", "hint": "use --overwrite to replace it, or name another file", "detail": {"path": "houses.ml"}}
# exit status 5; the rule, hint, detail of the JSON line it prints
$ ml fit --dry-run --overwrite --target price --output houses.ml houses.csv
{"ok":true,"command":"ml","schema":"ml.v1","data":{"model":"constant","task":"regression","rows":5,"columns":4,"target":"price","path":"houses.ml","bytes":340,"sha256":"299879cc4b9be8afb5c6029aa8c635693162dc7a6d6ef564a4a1a66b83f4f1d8","written":false,"summary":{"mean":"218000.000000"}},"dry_run":true,"planned_actions":[{"op":"replace","path":"houses.ml","bytes":340,"sha256":"299879cc4b9be8afb5c6029aa8c635693162dc7a6d6ef564a4a1a66b83f4f1d8"}],"meta":{"version":"0.1.0"}}

A damaged model is refused

The model file ends with the SHA-256 of every byte before it. damaged.ml is houses.ml with one byte altered.

Hold rows out, with a seed

--split train=0.8 --seed 3 chooses the rows by the seeded train/test split of the metrics library; the fit reports the held-out rows scored through the stored steps, and eval --split with the same seed scores the same rows. With 5 rows the test side is 1 row: this is only the shape of the answer.

Text columns: encode, then fit and score in one call

--cat NAMES declares columns of text, and a step has to read each one: encode column=NAME kind=onehot|label, freq column=NAME (the share of the training rows that hold the category) or hash column=NAME buckets=B (the first 8 bytes of SHA-256, modulo B). min-count=N puts the categories seen fewer than N times in the training rows into one bucket, __other__; unknown=refuse refuses a string the training rows never held; missing=zero turns an empty cell into zeros. The vocabulary is built from the training rows only, so the result does not depend on the row order or on --threads. The file is docs/examples/data/pets.csv: 76 generated rows, so the metrics show how the commands work and nothing about pets.

# pets.csv: 76 rows; species and city are text. Declared with --cat but read by no step, they are refused
$ ml fit --model logistic --cat species,city --target adopted --output pets.ml pets.csv

# exit status 8; the rule, hint, detail of the JSON line it prints
# Encoded, the fit is refused unless it is held out: no model file can hold the vocabulary

The limit. The model file has no string table, so a fit with a categorical step writes no file: --split fits and scores in one invocation, --dry-run reports, and any other fit is refused. Without a file there is nothing to predict or eval with, so a model with a categorical step cannot be applied to new rows from the command line.

Built to be read by an agent

ml introspect and ml skill are generated from the same tables the code parses its flags with, so they cannot disagree with the program. An agent can learn the interface, the limits, the rules and the authority from the binary itself. A test checks that every flag and every rule is in the table, in introspect, in skill, in the schema and in a fixture. Match on error.rule, not on the message; repair is null or an argv that can be run as it stands; --dry-run exits 9 and writes nothing. The exit codes are cancho’s agent-toolbox classes: 0 done, 1 the operating system failed, 2 a malformed call, 3 not found, 4 refused, 5 conflict, 8 the answer is no or a limit was reached, 9 a dry run completed.

The guarantees block of introspect and parts of skill are the pinned contract package’s generic text. They are wrong or too narrow for ml in six places (for example “read-only: it never writes”, although fit writes), listed in docs/cli.md section 8 so that nobody reads them as claims.

What it cannot do

  • Three models are reachable: constant, linear and logistic. k-means, decision trees and random forests exist as libraries with independent oracles and a manifest with wired = false; a plan naming one is ml.plan.model-not-built (docs/modules.md).
  • A model with a categorical step has no file. fit --cat NAMES reads declared text columns into a bytewise-sorted dictionary and an id matrix, with limits (docs/categorical.md), and encode, freq and hash turn them into numbers (docs/categorical-encoders.md). The string table is not in the model file, so such a fit is ml.model.vocabulary-not-stored unless it has --split (it scores the held-out rows and writes nothing) or --dry-run, and predict and eval take no categorical model from a file. A declared column that no step reads is ml.input.categorical-not-encoded; a text column that is not declared is ml.input.non-numeric, with --drop as the repair. Target encoding, categorical splits in trees and free text are not built.
  • Binary classification only, and --threads only does something in fit: eval accepts and checks it, and nothing in it is threaded.
  • One gate is red. The regression forest against scikit-learn’s: RMSE 8.1% apart where the tolerance is 3%. The algorithms differ (histogram against exact splits) and most of the gap is attributed to that; the tolerance is kept and the decision is the maintainer’s (evidence).
  • Not tested across machines. The bytes are verified on one Mac, arm64. A Linux x86-64 run is not done.
  • No CI workflow. The reader is a pinned dependency on cancho-table’s stores (cancho-table#44), so no sibling clone is needed, but cancho install needs the network and nothing here runs scripts/check.sh automatically.
  • Not built: the MCP server and ml-serve (issue #16).
  • Not planned in v1: neural networks and a GPU path. Boosting, naive Bayes, k-NN and multiclass are in the plan and not built.

Nothing in this list is a promise. docs/status.md has it as a table, with the document that measured each item.

Quick start

You need git, Rust, clang and Python 3, and network access for the clones and for cancho install, which fetches the pinned cancho-tools modules and cancho-table’s five numeric modules (the stores of cancho-table#44) into build/deps. Both are [dependencies.*] of cancho.toml, pinned to one commit each (cancho-table: 202b214372a0); nothing is cloned or copied. On a 16-core Mac at a load average of 3 to 5 with the compiler built, cancho install took 1.4 seconds and cancho build --bin ml 5.0 seconds, once each; the compiler build and the clones are extra.

Built in cancho, with an authority the compiler wrote

cancho is a language whose compiler writes down what a program may do (cancho authority). For ml that is the line below: it can read its arguments and the files named on its command line, allocate memory, create, append to, rename and remove files beneath a directory it opened itself, and write to the terminal. It cannot use the network, call foreign code, read the clock, read standard input or write a file by path. conc is in the row because fit --threads calls the threaded kernels of the linear algebra. The path extent is a run-time value, so the row names the verb, not the place: fs_read("").

# manifests/ml.authority.json
ml    args, conc, dir_read, dir_write, err_write, file_read, file_write, fs_read(""), heap, io_write

How fast

No speed is claimed for ml: the command line has not been timed. The libraries under it were timed on one shared Mac (arm64, 16 cores) at a load average of 2.4 or more, so every figure is flagged load >= 2 and none is a quiet-machine number. No run on a quiet machine exists, and the linear-algebra and model timings were taken with the summation order of one chain per block, not the 4-lane order the libraries use today. They are on the benchmarks page with their conditions, and these are the shape of them.

  • Where it is slower. Dense float linear algebra: on the 29 gate shapes, one thread, 8 match numpy and Accelerate and 21 do not, from 1.05 to 14.9 times slower; square gemm is 13.8 to 16.5 times slower. The same algorithm in C takes about as long, so the gap is the vendor library and the language (no SIMD vector type). Logistic regression is 1.4 to 1.5 times slower than numpy’s same algorithm. A log-loss is 3.0 times slower than a thin numpy version.
  • Where it is not. The triangular solves and small Cholesky match; k-means is level with scikit-learn (306 against 330 ms on 1,000,000 rows); the AUC took 24 ms against 86 ms for a thin numpy version on 1,000,000 scores.
  • Forests. Ten trees on 100,000 rows fit in 0.0516 s on one thread, where scikit-learn’s exact-split RandomForestClassifier took 1.06 s. Not a speed claim: the algorithms differ (64 quantile bins against exact thresholds).

Status: early, alpha

  • What is listed above works and is tested. The command line builds three models. Nothing here is for production.
  • One pre-registered gate is red, and the speed figures are from a loaded machine. Evidence and benchmarks say exactly what each shows.
  • The program is built with one pinned compiler revision, a4572ea, and no other is used.
