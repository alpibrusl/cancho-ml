# Status: what is built, what is not, what was measured

`ml` is early and alpha. It is not for production. This page says what is built, what is not, what has been measured (each figure with its source document and conditions) and what is open. A figure that has no source in this repository is not here.

All the measurements are from one machine, a Mac (arm64, Apple M4 Max, 16 cores, macOS 26.2), with the compiler at `a4572ea`. The machine is shared and was never quiet: every timing is flagged `load >= 2`, and no quiet-machine run exists. Correctness gates do not depend on the load. Nothing has been run on a second machine.

## What is built, and reachable from the command line

The command line is `ml fit | predict | eval | cv | describe | introspect | skill`; `ml-predict`, a second binary from the same sources, is `predict | describe | introspect | skill`; `ml-serve`, a third, serves one model file over HTTP. It builds six models: `--model constant` (the training mean for a regression, the majority class and its probability for a classification), `--model linear`, `--model logistic`, `--model kmeans`, `--model tree` and `--model forest`, the last five through a pipeline of fitted steps stored in the same file ([wiring.md](wiring.md), [wiring-trees.md](wiring-trees.md), [wiring-kmeans.md](wiring-kmeans.md), [modules.md](modules.md)).

| item | what it is | source |
|---|---|---|
| `fit`, `predict`, `eval` with `--model constant` | A regression of an integer, decimal or float target (the exact mean; for `eval`, the exact sum of squared errors and an `rmse`), or a binary classification (the majority class, the smaller label on a tie, the probability to six digits; `eval` gives the accuracy). | [cli.md](cli.md) sections 2, 3 |
| `fit`, `predict`, `eval` with `--model linear` and `--model logistic` | Least squares (ridge with `--l2`) and binary logistic regression (Newton, `--iterations`, `--l2`), fitted through the steps of a plan (`--step`, `--plan`: `impute`, `scale`, `encode`, `bucket`, and `freq` and `hash` for declared text columns) on the training rows; when every step reads numbers the fitted steps and the estimator are one `CML1` file, and `predict` (with `--proba` for the probability) and `eval` apply the stored steps. `--split train=F --seed N` holds out rows (the metrics library's split); `--positive LABEL` names the positive class; `--threads N` threads `fit`. `eval` gives RMSE, MAE and R2, or accuracy, precision, recall, F1, ROC-AUC and log-loss. An empty cell is a missing value that the plan must impute, else `ml.input.missing-value` with a repair. A prediction column that is empty in every row is a missing column of the schema (`ml.schema.mismatch`). | [wiring.md](wiring.md) |
| `fit`, `predict`, `eval` with `--model tree` and `--model forest` | A CART decision tree and a bagged forest with histogram splits and exact integer Gini, for a regression or a binary classification (`--task`, never inferred from the target), with `--trees`, `--max-depth`, `--min-leaf`, `--bins`, `--mtry`, `--bootstrap`, `--max-nodes`, the steps of a plan, `--split`, `--positive`, `--proba` and `--threads` (the forest is built by a static partition of the trees). A cell that is missing after the steps is accepted: the model learns a default side at each split. The file is model kind 7 with the summation order 3 (sequential sums), written byte for byte as an independent Python writer writes it. A fit takes at most 2^20 (1,048,576) training rows (`ml.input.too-many-rows`), a depth above 30 is `ml.limit.depth` and a tree needing more than `--max-nodes` is `ml.limit.nodes`. `--seed` is one flag: the seed of `--split` and of the bootstrap and feature draws. `fit` refuses to write a model file longer than `--max-bytes` (`limit.input-too-large`), the limit `predict` and `eval` read with. | [wiring-trees.md](wiring-trees.md) |
| `fit`, `predict`, `eval` with `--model kmeans` | A clustering with no target: `fit` needs no `--target` and refuses one (`args.conflict`), requires `--k` (1 to 1,024), runs `--iterations` Lloyd iterations (a fixed number, default 10) from `--init kmeans++` or `random` drawn from `--seed`, through the steps of a plan, and threaded by `--threads`. The answer holds the inertia, the rows of each cluster and the mean distance of each; `predict` prints the cluster of each row (`--distance` adds the squared distance to its centre); `eval` prints the same three numbers for another file or for the rows `--split` holds out. A cell still missing after the steps is refused (`ml.input.missing-value`), `k` above the training rows, `k * features + k + 1` above 131,072 and diagnostics above 2^24 floats are `ml.param.out-of-range` before anything is allocated. The file is model kind 6, its schema has no target (the target index is the number of columns) and the summation order is 2. A cluster that empties keeps its centroid. | [wiring-kmeans.md](wiring-kmeans.md) |
| the model module contract | A manifest per model (`lib/models/*/model.toml`), a generator (`scripts/gen_models.py`) for the dispatch, the flag and plan-key tables and the docs table, an admission script (`scripts/admit.py`, checks Q0 to Q11) and mutant modules that it must refuse (`tests/modules`). | [modules.md](modules.md) |
| the CSV reader | Integer, decimal and float columns, RFC 4180 quoting, a byte order mark, CRLF. A float is the nearest double, by cancho-table's exact reader (a pinned package dependency, not a copy). `nan`, `inf` and a non-number are refused with line and column, and so is an empty cell by the constant model; the pipeline models read it as a missing value. | [reader.md](reader.md) |
| declared text columns | `fit --cat NAMES` reads text columns as bytes into a dictionary sorted bytewise (`lib/core/dict.cho`) and an `i64` id tensor with a missing bitmap beside the float matrix (`lib/core/catmat.cho`); `--na-values`; limits on categories, bytes, pool and columns, each refused before allocation; UTF-8 validated. A declared column that no step reads is refused with `ml.input.categorical-not-encoded`; the loader for `predict` with a stored vocabulary is a library API. | [categorical.md](categorical.md) |
| encoders of text columns, and the string table | In `fit` of `linear`, `logistic`, `kmeans`, `tree` and `forest`: `encode` (one-hot, label), `freq` (count over rows, one rounding), `hash` (SHA-256, first 8 bytes big-endian, modulo B), a rare-category bucket (`min-count`, the category `__other__`) and the rules `unknown` and `missing`; the vocabulary is built from the training rows only. The model file of such a fit has a sixth section, the string table (bounded, checksummed, with the markers and the reader limits of the fit), and each categorical step is a stub in the `steps` section; a file with no categorical step has five sections. `predict` and `eval` read the text columns by name from the file alone, in any column order, count a string the training rows never held, and hash it into its bucket under a `hash` step. **The file holds the raw category strings of the training rows**; a `hash` step stores none. | [stringtable.md](stringtable.md), [categorical-encoders.md](categorical-encoders.md) |
| the model file `CML1` | Five to seven sections (the provenance section last), tensor records, a SHA-256 trailer. No timestamp, host or path. Written to a temporary name, synced and renamed. | [cli.md](cli.md) section 4, [design.md](design.md) section 4.1 |
| refusals | 89 rule tags in `introspect`, each with an exit code and whether a repair can exist; one JSON line against `ml.v1`. | [cli.md](cli.md), [design.md](design.md) section 8 |
| `--dry-run`, `--overwrite` | `fit --dry-run` answers what it would write and exits 9. Not run under `strace`. | [cli.md](cli.md) section 2 |
| limits | Twenty-one flags have a default and a ceiling: `--limit`, `--from`, `--max-rows`, `--max-columns`, `--max-cells`, `--max-line-bytes`, `--max-bytes`, `--log-max-bytes`, the four limits of the categorical columns, `--iterations`, `--k` and the six integer flags of the tree and forest (`--trees`, `--max-depth`, `--min-leaf`, `--bins`, `--mtry`, `--bootstrap`, `--max-nodes`). Each is checked before anything it sizes is allocated. | [cli.md](cli.md) section 2.2 |
| `introspect`, `skill` | Generated from the table the parser runs on. | [cli.md](cli.md) section 1 |
| `predict` from standard input | `predict -` and `predict` with no operand read the CSV from standard input, up to `--max-bytes`; the answer is the answer for the same bytes in a file. | [serving.md](serving.md) section 2 |
| `describe` | What a model file requires of a caller, as data: model, task, plan, columns by name and type, vocabularies with counts, markers, reader limits, classes, the columns of an answer. The field names are a contract. | [serving.md](serving.md) sections 4, 5 |
| `ml-predict` | The prediction half of `ml`, built from the same sources with its own `main`; its authority row has no write and no thread: `args`, `dir_read`, `err_write`, `file_read`, `fs_read("")`, `heap`, `io_read`, `io_write`. | [serving.md](serving.md) section 3, [`manifests/ml-predict.authority.json`](../manifests/ml-predict.authority.json) |
| `ml-serve` | Serves one model file over HTTP with cancho-web, cancho-schema and `http.server` (pinned stores, none copied): `POST /predict`, `POST /predict/batch`, `GET /model`, `GET /openapi.json`, `GET /health`. The request schema and the OpenAPI 3.1 document are built from `describe`; a record is rendered to the CSV `ml predict` reads and goes to the same function in the same process; the values of an answer are the text the command line prints; a number that cannot be written exactly for its column is refused, never rounded; refusals are `application/problem+json` with the rule; every answer carries the SHA-256 of the model file. One thread; the body, the records, the head and the idle time are bounded; it listens on every address of the host (the pinned compiler cannot bind one) and so needs `--token-file` or `--no-token`; the model changes by restart. Its authority row has the sockets and the clock and no write, thread, process or foreign call: `args`, `clock`, `conn_accept`, `conn_read`, `conn_write`, `dir_read`, `err_write`, `file_read`, `fs_read("")`, `heap`, `io_write`, `net_in("")`, `poll`. | [serving-http.md](serving-http.md), [`manifests/ml-serve.authority.json`](../manifests/ml-serve.authority.json) |
| the authority row of `ml` | `args`, `conc`, `dir_read`, `dir_write`, `err_write`, `file_read`, `file_write`, `fs_read("")`, `heap`, `io_read`, `io_write`; bounded; no foreign function; no `net_out`, `net_in`, `ffi` or `clock` (`ml-serve` alone holds `net_in` and `clock`). `conc` is there for `fit --threads` and `io_read` for `predict` from standard input, each with its reason in `tools.toml`. | [`manifests/ml.authority.json`](../manifests/ml.authority.json), [cli.md](cli.md) section 6 |
| run tracking and skew checks | Every `fit` writes a provenance section: the SHA-256 and size of the training file, its rows, and the count, minimum, maximum, exact mean and population standard deviation of each numeric feature (exact sums, rounded once; a column whose exact sum of squares passes the largest double stores the largest finite double as its deviation). `eval` prints `on` (`train`, `other`, `unknown`); `predict`, `eval` and `ml-serve` print `out_of_range` and `--max-out-of-range` refuses (`ml.predict.out-of-range`); `predict` prints `ignored_columns`; a file with no section is read and says so. `fit --track DIR` writes a canonical run record (no timestamp, host name, path outside `--root` or payload) named by the hash of the inputs that determine the model, and `eval --track DIR` an eval record beside it; `ml runs list`, `show`, `compare` and `verify` read them, and `verify` refits in memory and compares the model file's SHA-256. The directory of `--track` must exist (the pinned compiler cannot create one), at most 1,000 records of 262,144 bytes each, and `verify` replays a column carrying `--drop`, `--float` or `--cat` only below position 62 of the header. | [tracking.md](tracking.md) |
| `--log` | NDJSON records of counts, flags, rule tags and a hash; no cell, column name or path; bounded. | [cli.md](cli.md) section 5 |
| the reader as a package dependency | Five `[dependencies.*]` (`pow5`, `dec`, `flt`, `facc`, `reader`) on the stores of [alpibrusl/cancho-table#44](https://github.com/alpibrusl/cancho-table/pull/44), pinned to `202b214`; `scripts/check_table_pin.sh` checks the pin. | [reader.md](reader.md) section 1 |
| the numeric stores | 23 modules of `lib/core`, `lib/linalg` and `lib/metrics` (`ml.rng`, `ml.exact`, `ml.fsq`, `ml.matrix`, `linalg.chol`, `linalg.par`, `metrics.rank`, `metrics.splits` and 15 more) are committed as `.cancho-vcs` stores that another repository pins by git, rev and path; `scripts/publish_stores.py --check` compares them with a fresh publish of the sources, `scripts/check_stores_pin.py` checks that nothing is copied or consumed back, and `scripts/consume_stores.py` builds a package outside the tree that calls every module. The `pub` functions are the interface (`stores_api.txt`). | [stores.md](stores.md) |

## What is built as a library

Each has gates, an oracle and mutants (see [the evidence page](https://alpibrusl.github.io/cancho-ml/evidence.html)). The transforms, the pipeline, the metrics and splits, linear regression, logistic regression, k-means, decision trees and random forests are called by the verbs; the wiring has its own gates ([wiring.md](wiring.md), [wiring-trees.md](wiring-trees.md), [wiring-kmeans.md](wiring-kmeans.md)).

| item | what it is | source |
|---|---|---|
| tensor and linear algebra | Rank 1 to 4 descriptors; `dot`, `axpy`, `gemv`, `syrk`, `gemm`, Cholesky and triangular solves, with one written summation order (blocks of 256 terms, 4 lanes in a block, a fixed tree over blocks, Cholesky panels of 32) that does not depend on the thread count; the metrics and the transforms use the same function. | [linalg.md](linalg.md) section 2, [lanes.md](lanes.md) |
| random generator | SplitMix64, derived streams, eight registered stream kinds. | [rng.md](rng.md) |
| metrics and splits | Accuracy, precision, recall, F1, ROC-AUC (integers, midranks), RMSE, MAE, R-squared, log-loss; k-fold, train/test, stratified. | [metrics.md](metrics.md) |
| split strategies and cross-validation, from the command line | `fit --split` and `eval --split` with `--stratify`, `--split-group COLUMN` or `--split-by time:COLUMN`; `ml cv --folds K --repeats R` with the same three (an expanding window for a time split), the metrics of every fold and their mean and sample standard deviation, and `--emit-folds`. Every fitted step is fitted on the training rows of each fold alone. Nine `ml.split.*` rules. `--model constant` is not cross-validated. | [splits.md](splits.md) |
| linear and ridge regression | Normal equations, Cholesky. Dependent columns are refused by a relative pivot test (a pivot must exceed 2^-40 of its own diagonal element), not by the sign of a rounded number. | [models-linear.md](models-linear.md) section 3.1 |
| logistic regression, binary | Newton, a fixed number of iterations, optional l2. | [models-linear.md](models-linear.md) |
| k-means | Seeded k-means++ or random initialisation, a fixed number of Lloyd iterations, the lowest index wins a tie, an empty cluster keeps its centroid. Called by `--model kmeans`. | [models-linear.md](models-linear.md) |
| decision trees and random forests | Histogram split search, exact integer Gini, a learned default side for missing values, threaded over trees. Binary classification and regression. Called by `--model tree` and `--model forest`. | [models-tree.md](models-tree.md) |
| transforms | `impute` (mean, median, constant), `scale` (min-max, standard), `encode` (one-hot, label), `bucket` (width, quantile); fitted on the training rows only, with a record per step; their sums use the package's summation order. | [transforms.md](transforms.md) |
| pipeline | A plan text with one canonical form, fitting a chain of steps, matching input columns by name, and one `CML1` file that holds the plan, the schema, every fitted step and the estimator payload. | [pipeline.md](pipeline.md) |
| the path check of the test tools | `models-check`, `tree-check`, `reader-check`, `linalg-check` and `metrics-check` refuse a path with two dots in a row (`path.dotdot`, exit 2) and trap on no missing operand; they are test drivers, not libraries. | [lanes.md](lanes.md) section 1 |
| the sum order in a library model file | A file of model kind 4 to 7 ends its `meta` section with a `u32 sum_order`: 2 for the 4-lane order of kinds 4 and 5, 3 (sequential sums in a fixed row order) for kind 7, the tree and forest, which use no lane sum; a reader refuses another value for the kind with `ml.model.version`. Kinds 1 to 3, the constant models, have no such field. `ml` writes kinds 4, 5, 6 and 7. | [design.md](design.md) section 4.1 |

## What is not built

| item | state |
|---|---|
| text columns, the rest of issue 21 | Target encoding, native categorical splits in trees and free text. A declared column that no step reads is `ml.input.categorical-not-encoded`. A hashed column is still interned while the fit reads the file (`--max-categories` bounds it there), though the file stores none of its strings. |
| `eval --threads` | accepted and checked; nothing in `eval` is threaded |
| the MCP server | not built; how it would be derived is [cli.md](cli.md) section 9 |

| boosting, naive Bayes, k-NN | in the plan ([design.md](design.md) section 1), not built |
| imputation in the constant model | `--model constant` refuses an empty cell; the pipeline models take it as a missing value |
| neural networks, GPU | not planned in v1 |
| other platforms | macOS arm64, Linux x86-64 and Linux aarch64 (a Raspberry Pi 5, by hand, outside the workflow) agree on 88 fingerprint lines for 22 fits (`docs/bench/xplat_fp.txt`, `scripts/xplat_check.py`; compiler `a4572ea`, commit `43efd8f`, the golden as re-recorded for the provenance section); the workflow covers the first two; any other platform is untested |
