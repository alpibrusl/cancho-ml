Worked examples

Four classic datasets, solved by the real ml binary and checked against scikit-learn on the same two files. For thirteen stories on invented data instead, from a bicycle shop to a marketing campaign, see the stories.

What this is. For each dataset the same train.csv and test.csv go to ml and to scikit-learn. The ml commands and what they print are on this page exactly as run, and the page is regenerated from the built binary by scripts/check_docs.sh, which fails if a character drifts. The scikit-learn column is not computed by that check: it is read from docs/examples/reference.json, which scripts/examples_data.py wrote once, and each table says with which version.

What the comparison is worth. What was compared, which scikit-learn parameters correspond to --l2, and the tolerances, with the reason for each, were written before any example was run: docs/examples.md. A row outside its tolerance says differs and the cause is written next to it. These are teaching datasets: nothing here says anything about medicine, botany or chemistry, and nothing about how fast ml is.

How to read the tables

The ml column is the string ml printed, unchanged. The scikit-learn column is the float scikit-learn computed, written with the shortest decimal that reads back to the same double. The difference is the absolute value of the two read as doubles. The tolerance is the one fixed in docs/examples.md section 3: linear and ridge, 1e-9 relative (both are direct solves); logistic coefficients, 1e-6 relative (ml's Newton method is exact to rounding, and scikit-learn's L-BFGS solver stops short of the optimum even at tol=1e-12, as that document explains); the logistic log-loss and ROC-AUC, 1e-6 absolute; accuracy, precision, recall and F1, equal. ml has no stopping rule, so each logistic fit also runs with four times the iterations and the table below it shows what changed.

Breast Cancer Wisconsin: the obvious command is the wrong one

Predict whether a tumour is benign (label 1) or malignant (label 0) from 30 numbers measured on cell nuclei in digitised images of a fine-needle aspirate. Logistic regression on standardised features (scale kind=standard, population variance, which is what scikit-learn's StandardScaler does). The train and test files are a fixed seeded split, stratified by the class.

426 training rows and 143 test rows, 30 features (breast_cancer_train.csv, breast_cancer_test.csv); target benign, the positive class (label 1) is 62.7% of the training rows.

What the first command shows. The first command, with no penalty, is the one most people would type. It classifies every training row correctly when it is allowed to run, which means a plane separates the two classes; the penalty-free optimum is then at infinity and there is nothing for Newton's method to converge to. ml sees it at the second pass, where the summed loss is under ln 2 (every row has a positive margin), and refuses the fit with ml.fit.separable: the pass, the loss, the bound and the norm of the coefficients are in detail, and the repair is an argv that adds a penalty. The fit that was compared has --l2 0.01, and it is the one whose iteration count does not matter. The scikit-learn parameters that correspond to it are in the line under the first table.

Diabetes progression: linear regression and ridge

Predict a measure of disease progression one year after baseline from ten baseline variables (age, sex, body mass index, blood pressure and six blood serum measurements), as bundled with scikit-learn: the ten features are already mean-centred and scaled, so the fit needs no --step. Ordinary least squares, then ridge with --l2 0.05. ml minimises the squared error plus l2 times the squared coefficients, the intercept not penalised: scikit-learn's Ridge(alpha=0.05). The train and test files are a fixed seeded split.

331 training rows and 111 test rows, 10 features (diabetes_train.csv, diabetes_test.csv); target progression.

Iris: versicolor against virginica

Fisher's flower measurements restricted to two of the three species (versicolor, label 0, and virginica, label 1; setosa is dropped), which overlap. This is the example of the README.

What the first commands show. ml reads the type of a column from the file in front of it. color_intensity has two decimals in the train file and six in the test file, so the fit worked and the scoring of the test file was refused with ml.schema.mismatch, which says which column. --float color_intensity at fit time reads it as a float, and the stored model then accepts the test file. The penalty-free fit then repeats the breast-cancer lesson: the classes are separable, so it is refused with ml.fit.separable and a repair.

Not covered

Popular tasks that need something ml does not have. Nothing is claimed about running them.

  • Titanic (survival, a binary label) has columns of text: Name, Sex, Ticket, Cabin and Embarked. What works on a file of that shape: Sex and Embarked declared with --cat (and the empty Embarked cells taken with missing=zero) and read by encode steps, an impute step for the empty Age, --drop Name,Ticket,Cabin for the columns of free text and identifiers (each has hundreds of distinct values, where the default limit is 64 categories), fit writing the model file with the training strings, and predict and eval reading that file for the second file of the task, the rows to predict, which may hold a category the first file did not (counted) and its columns in another order. This combination was not run on the Titanic file, which is not in this repository and was not downloaded; the same pieces run on a generated file (status).
  • House Prices (a regression) has many columns of text categories, where an empty cell often means none. The same pieces: each text column named in --cat (up to 128 by default, 4,096 at most) and read by a step (hash column=* reads every declared column that no other step reads, and stores none of their strings), fit writing the model file and predict reading it for the rows to predict. Not run.
  • Clustering (iris without its label, a customer segmentation) has no target. ml --model kmeans fits it, and the guide runs it on the committed iris files. It is not one of the four examples above because there is no label to score against: its gate against scikit-learn gives scikit-learn the initial centres of ml, since the two programs draw different ones (scripts/gate_wire_sklearn.py kmeans, the evidence page).
  • Digit Recognizer (handwritten digits) has ten classes and images with many columns. ml is binary only (a third label is ml.label.not-binary), and how large images would be read has not been looked at.
