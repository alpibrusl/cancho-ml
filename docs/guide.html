The guide

Classical ML as a command line an agent can read: fit, apply and score a model on a CSV, with exact sums, bounded resources, structured refusals and a machine-verifiable authority.

A command line and flags, not a chat box. The same tool for a person and for an agent. It builds seven models: the constant one (the training mean or the majority class, a baseline with the whole path around it), linear regression, logistic regression, k-means (clusters, and no target), a decision tree, a random forest and gradient-boosted trees, the last six through a pipeline of steps that is fitted on the training rows and stored with the model in one file.

Why cancho-ml?

Most ML tools optimise for how many models they offer. ml is built to be predictable first, and offers seven models and a pipeline.

  • Explicit typesA column is an integer, a decimal or a float, read to the nearest double by cancho-table’s exact reader. nan, inf, an empty cell and a cell that is not a number are refused with the line and the column. docs/reader.md
  • Exact where a sum decidesThe mean of an integer or decimal target and the sum of squared errors are exact integers, not floats; a float target is summed exactly and rounded once. A test compares every digit with Python’s fractions.Fraction. The rmse is three IEEE steps after the exact sum, and says so. docs/cli.md
  • The same bytesA model file holds no timestamp, host or path. The same data, plan and seed give the same bytes whatever the working directory or the spelling of the path, and at every --threads from 1 to 16 (linear and logistic, one Mac); across machines it holds for 22 fits on macOS arm64 and Linux x86-64 and is not tested on any other platform. Evidence
  • Bounded resource useRows, columns, cells, line length, model size, log size and the categorical dictionary each have a limit flag with a default and a ceiling, checked before anything sized by the input is allocated (the limits). Peak memory is measured for one case, the reader’s refusal of a 200 MB file (1.5 MB); no gate measures the memory of a fit.
  • No implicit network accessThe authority row lists what the program can reach: no net_out, net_in, ffi or clock, no standard input and no write by path. cancho authority derives it, and scripts/manifest.py --check fails if the binary differs from the committed manifest.
  • Machine-readable errorsOne JSON line against a schema (ml.v1). A refusal is {code, rule, message, hint, repair, detail} with a stable <area>.<name> rule tag. docs/design.md
  • Numeric modules other repositories pinThe random generator, the matrix with its missing-cell bitmap, the exact sums, the Cholesky factor and solves, the ranks and the splits are committed as 23 .cancho-vcs stores. A consumer pins them by git, rev and path and copies nothing; a script fails when a store differs from a fresh publish of the sources. docs/stores.md
  • Repair hintsA refusal says how to fix the request: an argv to run as it stands, or why there is none.
  • A model file that checks itselfCML1: sections, tensor records and a SHA-256 trailer. Every truncation and every flipped byte of a small model is refused. Evidence
  • Text columns, encoded by a written ruleColumns declared with --cat are read into a bytewise-sorted dictionary. encode (one-hot, label), freq and hash (SHA-256) turn them into numbers, with a rare-category bucket and rules for an unseen string and an empty cell; a Python oracle agrees bit for bit on 515 runs. The model file of such a fit stores the training strings in a bounded, checksummed string table, so predict and eval read the text columns by name from the file alone. Evidence
  • Capability introspectionml introspect prints the flags, limits, rules and authority; ml skill prints a guide for an agent. Excerpts below

Fit and score a classification

--task classification needs an integer target with exactly two values. The prediction is the class with more rows (the smaller label on a tie) and the probability is the share of the larger label’s rows, to six digits. predict comes in pages: --limit and --from, and next is where to continue. This example uses shop.csv: id,visits,spend,bought and six rows, four of them with bought = 1.

Read floats exactly

A cell with an exponent, a leading or trailing point or more than 12 digits is a float without being named (--float NAMES forces it). It is read to the nearest double, ties to even. The mean of a float target is the exact sum of the doubles over the count, rounded once, and written as the shortest decimal that reads back to the same double. This example uses sensor.csv: id,x,reading and the readings 1e1, 2.75, 3e-1 and 5.5.

Check before you write

An existing output is refused unless --overwrite is given. --dry-run reads, checks and fits, runs every check the write would, and answers with the file it would write: exit 9, and nothing created or changed. The file is written to a temporary name beside the final one, synced and renamed over it; that this keeps a reader from seeing half a model, and two writers racing on one output, were not tested.

$ ml fit --target price --output houses.ml houses.csv
{"rule": "conflict.exists", "hint": "use --overwrite to replace it, or name another file", "detail": {"path": "houses.ml"}}
# exit status 5; the rule, hint, detail of the JSON line it prints
$ ml fit --dry-run --overwrite --target price --output houses.ml houses.csv
{"ok":true,"command":"ml","schema":"ml.v1","data":{"model":"constant","task":"regression","rows":5,"columns":4,"target":"price","path":"houses.ml","bytes":416,"sha256":"df669ebf009e182d179668967f9c248bc3bfed3383141089bb8759e5c569c62a","written":false,"summary":{"mean":"218000.000000"}},"dry_run":true,"planned_actions":[{"op":"replace","path":"houses.ml","bytes":416,"sha256":"df669ebf009e182d179668967f9c248bc3bfed3383141089bb8759e5c569c62a"}],"meta":{"version":"0.1.0"}}

A damaged model is refused

The model file ends with the SHA-256 of every byte before it. damaged.ml is houses.ml with one byte altered.

$ ml eval --model-file damaged.ml houses.csv
{"rule": "ml.model.checksum", "hint": "the file changed after it was written"}

It says what it does not do

The --model list is the list of what is built. There are no stand-in models, and a test pins that. A prediction that is not a finite number (a feature near the largest double times a coefficient above 1) is a refusal too, ml.predict.non-finite, with the row and the column in detail and no cell written; predict, ml-predict, eval and ml-serve raise it from one function, over every row scored and not only the page.

$ ml fit --model knn --target price --output knn.ml houses.csv
{"rule": "args.bad-value", "detail": {"flag": "--model", "value": "knn", "expected": "constant/linear/logistic/kmeans/tree/forest/boost/softmax"}}
# exit status 2; the rule, detail of the JSON line it prints
$ ml fit --target prize --output typo.ml houses.csv
{"rule": "ml.input.unknown-column", "hint": "names are compared exactly, byte for byte", "detail": {"flag": "--target", "name": "prize"}}
# exit status 3; the rule, hint, detail of the JSON line it prints

Splits and cross-validation

--split train=F is a seeded random holdout; --stratify keeps the class proportions, --split-group COLUMN keeps every group on one side and --split-by time:COLUMN holds out the newest rows (a number or an ISO-8601 date or datetime). ml cv --folds K --repeats R scores a model on every fold and writes no file: the per-fold metrics, their mean and their sample standard deviation, and with --emit-folds the fold of every row, as data. Every fitted step is fitted on the training rows of its fold alone. Two strategies at once, cv with --split and a stratified regression are refused with a rule and a repair where one exists. The assignment is this tool's seeded stream, not scikit-learn's: what is compared with scikit-learn is the invariants and the metrics on the same explicit folds (the gates, docs/splits.md). visits.csv is generated data.

The strings are in the file. The string table of the model file holds the raw category strings of the training rows, with their counts, the column names and the missing-value markers: whoever has the model file has those values. A hash step stores none of the strings of its column, and encode min-count=N still stores every distinct string, because the counts are the state. A pipeline that must not carry its category values hashes them. A file with no categorical step has no table. The table is bounded (131,072 strings, 8 MiB of string bytes, 12 MiB in all; ml.limit.string-table), checksummed, and refused with ml.model.string-table when it is damaged (docs/stringtable.md).

Explain a model

A model that cannot be explained can only be trusted by its score. ml importance says which columns a model relies on and ml dump prints the model itself; neither fits or changes anything. A linear or logistic model gets the standardised coefficients (the coefficient times the standard deviation of the column the model sees, and each column's share of the sum); a column with no stored deviation is refused with ml.importance.no-scale. A tree or a forest needs nothing the file does not hold: every node stores the rows that reached it, so the impurity decrease of every split (scikit-learn's feature_importances_) is computed from the model file alone, and how often and how high a feature splits is printed beside it under its own names. --data FILE adds the permutation importance on held-out rows: one raw column at a time is shuffled among the rows, the stored steps are applied again, and the drop of the metric is reported with its mean and standard deviation over seeded repeats; a missing cell travels with its row, and no thread count, no order of the columns of the file changes a number. describe and the GET /model of ml-serve carry the table that needs no data. Boosted trees

--model boost fits additive trees to the gradients and hessians of squared error (a regression) or of the logistic loss (a binary classification), one histogram tree a round with a Newton step in each leaf times --learning-rate. --rounds, --learning-rate, --max-depth, --min-leaf, --bins, --l2, --subsample (seeded from the seed and the round) and --early-stopping are the flags; early stopping is refused unless --split declares a held-out part, which the stopping rule never reads, and refused with --split-group and --split-by (ml.split.combination, with a repair that drops it): its validation rows are a random tenth of the training rows, which a group or a time split cannot allow. A cell that is missing is accepted. Every sum is sequential in a fixed order (summation order 3 in the file, model kind 8), so the bytes are the same at every --threads.

# early stopping keeps rows out of the fit, so it is refused unless a held-out part is declared with --split

Predict from standard input, describe a model file, and ml-predict

ml predict reads the CSV from standard input for the operand - or for no operand; a file named - is ./-. The bytes are read once, up to --max-bytes (16 MiB by default), and the reader's two passes run over them, so the answer for the bytes on standard input is, byte for byte, the answer for the same bytes in a file (a refusal that names a file says - instead). ml describe --model-file M prints, as data, what a model file requires of a caller: the model and its task, the plan, the columns by name and type, the vocabularies with counts, the missing-value markers, the reader limits, the classes and the columns of an answer. Its field names are a contract (docs/serving.md): a server builds its request schema from them. ml-predict is a second binary built from the same sources. Serve a model over HTTP with ml-serve

ml-serve serves one model file with cancho-web (docs/serving-http.md). It is a third binary from the same sources. It reads the model file once and decodes it once, builds the request schema from what describe says (a member for each column, the enum of the categories the file lists in full, null only where the model takes missing cells) and the OpenAPI 3.1 document from the same declaration, and answers one request at a time on one thread. A record becomes the CSV text ml predict would read and goes to the same function in the same process; the values in the answer are the text the command line prints, written as JSON numbers. A number that cannot be written exactly as the type of its column is refused with its JSON Pointer and never rounded. A refusal is application/problem+json with a rule field, and every answer carries the SHA-256 of the model file. ml-serve listens on 127.0.0.1 by default and needs no token there; --bind all listens on every address of the host and requires --token-file.

Call it from an agent: ml-mcp

ml-mcp is a fourth binary from the same sources (docs/mcp.md). It speaks the Model Context Protocol (revision 2025-06-18) over standard input and output, one JSON-RPC message per line, and offers twelve tools: fit, predict, eval, cv, describe, importance, dump, introspect, runs_list, runs_show, runs_compare and runs_verify. They are derived from the flag table: scripts/mcp_tools.py writes the name, description, inputSchema and outputSchema of each into docs/mcp/tools.json, and scripts/check_mcp_tools.py fails when a flag is added to the table and the file is not regenerated. A call runs the code of ml in the same process (no subprocess, no exec): structuredContent is the line ml prints for the same command, content[0].text its text form, a refusal is a tool result with isError: true carrying the rule, the exit code and the repair as ml prints them, and a malformed message is a JSON-RPC error.

A client registers it with a command and arguments: {"mcpServers": {"cancho-ml": {"command": "/path/to/ml-mcp", "args": ["--root", "/path/to/data"]}}}. It is read-only unless started with --allow-write (which needs --root): without the flag fit is not listed, the write flags are not offered by the other tools, and a call that names one is the tool error mcp.read-only. Paths are relative to --root and checked as the command line checks them. predict takes file or records, a JSON array of objects rendered to the CSV the predictor reads by the byte rule of ml-serve. A message over --max-message-bytes (1 MiB by default) is refused before it is kept; the server reads one message at a time, has no clock and so no deadline, and reads a notifications/cancelled for a call in progress after the call has answered. Its authority row is the row of ml: no network, no listener, no clock, no process. A session on the data of the first example:

Built to be read by an agent

ml introspect and ml skill are generated from the same tables the code parses its flags with, so they cannot disagree with the program. An agent can learn the interface, the limits, the rules and the authority from the binary itself. A test checks that every flag and every rule is in the table, in introspect, in skill, in the schema and in a fixture. Match on error.rule, not on the message; repair is null or an argv that can be run as it stands; --dry-run exits 9 and writes nothing. The exit codes are cancho’s agent-toolbox classes: 0 done, 1 the operating system failed, 2 a malformed call, 3 not found, 4 refused, 5 conflict, 8 the answer is no or a limit was reached, 9 a dry run completed.

The guarantees block of introspect and parts of skill are the pinned contract package’s generic text. They are wrong or too narrow for ml in six places (for example “read-only: it never writes”, although fit writes), listed in docs/cli.md section 8 so that nobody reads them as claims.

What it cannot do

  • Seven models are reachable: constant, linear, logistic, k-means, tree, forest and boost (docs/models-boost.md, docs/wiring-trees.md, docs/wiring-kmeans.md, docs/modules.md). k-means is not scored against a label, runs a fixed number of iterations with no stopping rule, scales nothing by itself (add a scale step), refuses a missing cell, and keeps the centroid of a cluster that empties where scikit-learn moves the farthest point to it. A tree, forest or boosted fit takes at most 1,048,576 training rows (ml.input.too-many-rows), the bound of the tree library’s exact Gini comparison; a cell that is missing is accepted by a tree, forest or boosted model, which learns a side for it at each split, and refused by linear and logistic without an impute step (ml.input.missing-value). A tree or forest file is model kind 7 and a boosted file is model kind 8, both with the summation order 3 (sequential sums). --seed is one flag: the seed of --split, of a forest’s bootstrap and of a boosted model’s row sample and validation split. A boosted fit is sequential round by round: --threads only bins the columns, and there is no column sampling. fit refuses to write a model file longer than --max-bytes (limit.input-too-large), because predict could not read it.
  • The model file of a categorical step holds the training strings, within bounds. fit --cat NAMES reads declared text columns into a bytewise-sorted dictionary and an id matrix, with limits (docs/categorical.md), and encode, freq and hash turn them into numbers (docs/categorical-encoders.md). The file stores them in a string table (docs/stringtable.md): at most 131,072 strings, 8 MiB of string bytes and 12 MiB, else ml.limit.string-table; only the strings bound is reachable from the command line, because the reader’s own limits refuse the others first. A hashed column is still interned while the fit reads the file, so --max-categories bounds it there; the file stores none of its strings. predict and eval take no --cat, --na-values or limit flag. A declared column that no step reads is ml.input.categorical-not-encoded; a text column that is not declared is ml.input.non-numeric, with --drop as the repair. The same rows in any order give the same string table, schema and categorical steps; the numeric steps that sum and the estimator follow the order of the rows. Target encoding, native categorical splits in trees and free text are not built.
  • Binary classification only, and --threads only does something in fit: eval accepts and checks it, and nothing in it is threaded.
  • One gate is red. The regression forest against scikit-learn’s: RMSE 8.1% apart where the tolerance is 3%. The algorithms differ (histogram against exact splits) and most of the gap is attributed to that; the tolerance is kept and the decision is the maintainer’s (evidence).
  • Three platforms agree; no other is tested. macOS arm64, Linux x86-64 and Linux aarch64 agree on 112 fingerprint lines for 28 fits (every model kind, 1 and 8 threads: the SHA-256 of each model file and of each predict and eval answer), with compiler 0207556 (the first 88 lines are those the golden had before the boosted model, unchanged; the 24 lines of its 6 fits are appended; the model file holds the pin text): a Mac (macOS 26.2), an Ubuntu 26.04 workstation (Intel Core i7-1260P) and a Raspberry Pi 5 (Linux 6.18, aarch64). Quick start

You need git, Rust, clang and Python 3, and network access for the clones and for cancho install, which fetches the pinned cancho-tools modules and cancho-table’s five numeric modules (the stores of cancho-table#44) into build/deps. Both are [dependencies.*] of cancho.toml, pinned to one commit each (cancho-table: 202b214372a0); nothing is cloned or copied. Built in cancho, with an authority the compiler wrote

cancho is a language whose compiler writes down what a program may do (cancho authority). For ml that is the first line below: it can read its arguments, the files named on its command line and, for predict -, standard input, allocate memory, create, append to, rename and remove files beneath a directory it opened itself, and write to the terminal. It cannot use the network, call foreign code, read the clock or write a file by path. ml-predict, the second line, has the same row without conc, dir_write and file_write: it writes nothing but its answer. ml-serve, the third line, has the row of ml-predict without standard input and with the sockets of a server: net_in for the port, conn_accept, conn_read, conn_write and poll for the loop, and clock for the idle timeout and the access log. It writes no file, starts no thread and no process, calls no foreign code and opens no outbound connection. ml-mcp, the fourth line, has the row of ml: no network, no listener, no clock, no process, no foreign code. conc is in the row of ml because fit --threads calls the threaded kernels of the linear algebra. The path extent is a run-time value, so the row names the verb, not the place: fs_read("").

How fast

No speed is claimed for ml: the command line has not been timed. The libraries under it were timed on one shared Mac (arm64, 16 cores) at a load average of 2.4 or more, so every figure is flagged load >= 2 and none is a quiet-machine number. No run on a quiet machine exists, and the linear-algebra and model timings were taken with the summation order of one chain per block, not the 4-lane order the libraries use today. They are on the benchmarks page with their conditions, and these are the shape of them.

  • Where it is slower. Dense float linear algebra: on the 29 gate shapes, one thread, 8 match numpy and Accelerate and 21 do not, from 1.05 to 14.9 times slower; square gemm is 13.8 to 16.5 times slower. The same algorithm in C takes about as long, so the gap is the vendor library and the language (no SIMD vector type). Logistic regression is 1.4 to 1.5 times slower than numpy’s same algorithm. A log-loss is 3.0 times slower than a thin numpy version.
  • Where it is not. The triangular solves and small Cholesky match; k-means is level with scikit-learn (306 against 330 ms on 1,000,000 rows); the AUC took 24 ms against 86 ms for a thin numpy version on 1,000,000 scores.
  • Forests. Ten trees on 100,000 rows fit in 0.0516 s on one thread, where scikit-learn’s exact-split RandomForestClassifier took 1.06 s. Not a speed claim: the algorithms differ (64 quantile bins against exact thresholds).
