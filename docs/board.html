Experiments board

Load the run records of ml runs and read them as a table, a comparison and a chart. The page recomputes every run id from the record’s bytes and lists everything that does not add up. Nothing is sent anywhere: the files are read and hashed in this page and never leave your machine.

Load runs

Drop files on this page, choose them, or paste text. It reads the output of ml runs list DIR, the output of ml runs show DIR ID, and the record files DIR/*.json (run records and eval records), several at once. Each load adds to the runs shown.

The sample is real records: three runs of ml fit --track on docs/examples/data/iris_train.csv (the two fits of scripts/demo.sh and a k-means) and the eval record ml eval --track wrote for the first, exactly as the tool wrote them.

    What the page checks, and what only the tool can

    For each run record the page hashes the bytes of its inputs with SHA-256 (the browser’s crypto.subtle, or a built-in routine when the browser has none) and compares the result with the record’s id, and hashes the record up to its check member and compares that too. A record edited by one byte is flagged. This shows that a record is consistent with itself.

    It does not show that the model can be rebuilt. The page cannot verify a run: ml runs verify DIR ID re-fits from the training file the record names and compares the SHA-256 of the model file, and only the tool can do that, because it needs the training file and the same compiler build. The page never says “verified”; it gives the command to copy.

    A list from ml runs list carries no inputs, so a run known only from a list is marked list only and its id is not recomputed. The design, the rules and the checks of this page are in docs/board.md.
